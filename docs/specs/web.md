# A-04 — Веб и PWA v1.0: функциональная спецификация

**Статус: утверждено владельцем 10.11.2026. Пересмотрено 11.11.2026: «минимальный v1».** Основа: [A-01](../research/competitors.md), [A-02](../research/audience.md), [архитектура](../architecture.md), [спецификация расширения](extension.md).

Keep & Cook — личная библиотека, в которой быстро сохранить рецепт с сайта и удобно готовить по нему.

## Главный принцип: минимум

Проблема больших приложений в том, что на экране слишком много мест, куда можно нажать. В v1 интерфейс оставляет только два сценария:

1. **Найти рецепт → открыть → готовить.**
2. **Добавить рецепт:** ссылкой или вручную.

Всё, что не обслуживает эти два сценария, убирается из UI. **Данные и схема БД при этом не меняются:** коллекции, теги и избранное остаются в таблицах, сохраняются при импорте и редактировании, попадают в экспорт и участвуют в поиске. Миграции не нужны. Если пользователи попросят, функцию можно вернуть в интерфейс без потери данных.

Правило для новых функций: элемент интерфейса появляется, только если без него нельзя выполнить один из двух сценариев или его просили реальные пользователи (данные G-04, G-05, аналитики).

## Что убрано из UI в v1

| Убрано | Почему | Что остаётся в данных |
|---|---|---|
| Теги (фильтры, чипсы, поле в редакторе) | Объём библиотеки — десятки рецептов, поиска хватает | `tags` пишутся из импорта, ищутся поиском |
| Коллекции (чипсы, «Manage collections», поле в редакторе) | То же | Таблицы `collections`, `recipe_collections` |
| Коллекции по умолчанию при регистрации | Пустые Breakfast/Lunch/Dinner/Snacks — шум у нового пользователя | Существующие у старых пользователей не удаляются |
| Избранное (раздел, кнопка на карточке) | Дублирует поиск и «недавние» | `favorite_recipes` |
| Сортировка | Всегда «новые сверху» | — |
| Сайдбар и нижняя навигация | Три пункта не требуют навигационной панели | — |
| Переключатель темы в шапке | Тема по системе; ручной выбор в меню аккаунта | — |
| Мета в карточке библиотеки (дата изменения, число ингредиентов, описание, чипсы) | Карточка = фото + название + одна строка «время · сайт» | — |
| Обязательное описание | Лишнее трение при ручном вводе | Поле `description` nullable в БД |
| Поле «Photo URL» в ручной форме | Почти никто не заполнит | `image_url` из импорта |

## Карта экранов

```text
Публичная зона
  /                       Лендинг: оффер + демо по ссылке, расширение, CTA
  /login, /register        Вход/регистрация с сохранением next и черновика
  /forgot-password, /reset-password
  /privacy, /terms

Личный раздел
  /dashboard              Библиотека: поиск + сетка карточек
    ?q=                   Запрос поиска синхронизирован с URL
  /dashboard/recipes/:id   Адресуемая карточка (Should; до этого — состояние внутри /dashboard)
  /dashboard/settings      Экспорт, пароль, тема, выход, удаление аккаунта
  диалог «Добавить»        Ссылка или вручную → редактор
  cook mode поверх карточки

Вход извне
  handoff из расширения → auth → редактор
  /share                   Android Web Share Target (W-12) → auth → редактор
  YouTube URL              После X-01, через то же поле ссылки
```

Старые URL-параметры `collections` и `tags` игнорируются без ошибки. `/dashboard/favorites` редиректит на `/dashboard`.

## Экраны

### Шапка (вместо сайдбара и нижней навигации)

`[Логотип]  [Поиск………]  [+]  [Аккаунт ▾]`

- Логотип — наша иконка (`src/assets/Logo.svg` через компонент `BrandMark`), ведёт в библиотеку.
- На каждой странице, кроме библиотеки (настройки и т.п.), есть явная кнопка «Back to recipes»: одного логотипа для возврата недостаточно.

- Меню аккаунта содержит Settings, Theme (System/Light/Dark) и Sign out.
- На телефоне шапка однострочная: логотип, иконка поиска (раскрывает поле), «+», аккаунт. Над первой карточкой нет ничего, кроме шапки.
- Кнопка «+» живёт в шапке, а не плавает поверх контента. Отдельная FAB не нужна.

### Библиотека

- Сетка карточек: 1 колонка на узком телефоне, 2 на широком телефоне и планшете, 3–4 на десктопе.
- Карточка: фото одного размера у всех карточек (4:3, обрезка `object-cover`; без фото — наш логотип на приглушённом фоне), название до двух строк и одна строка «время · сайт-источник». Больше ничего.
- Поиск одной строкой по названию, ингредиентам и тегам (теги ищутся, но не показываются). Под полем при активном запросе — «N рецептов · Очистить».
- Порядок: новые сверху.
- Пустая библиотека: «Вставьте ссылку на рецепт» (поле прямо на экране), «или напишите вручную», а ниже ненавязчиво — «Установить расширение для Chrome».
- Пустой результат поиска: «Ничего не нашлось по „…“» и «Очистить».

### Карточка рецепта

Порядок: фото (если есть) → название → одна строка «источник ↗ · время · порции» (только распознанные поля) → **Start cooking** → ингредиенты → шаги.

- Описание показывается, только если оно не пустое и не совпадает с названием.
- Edit и Delete спрятаны в меню «⋯». Delete — с подтверждением.
- Без даты изменения и без чипсов.
- Офлайн доступны только чтение и готовка.

### Добавление

1. Диалог «Добавить рецепт»: одно поле «Вставьте ссылку» с кнопкой «Импорт», под ним ссылка «или написать вручную».
2. Импорт: загрузка → редактор с черновиком. Если черновик неполный, вверху строка «Не нашли: шаги, фото». Ошибки: неверный URL, сайт блокирует, рецепт не найден, таймаут, лимит. При любой ошибке есть «Повторить» и «Написать вручную» (URL сохраняется как источник).
3. Повторный импорт уже сохранённой ссылки открывает существующий рецепт (W-05).

### Редактор (ручной ввод и правка импорта)

Видимые поля:

- **Название** (обязательно)
- **Ингредиенты** — отдельное поле на каждый ингредиент, кнопка «Add ingredient» и крестик удаления у строки. Enter добавляет следующую строку, Backspace в пустой строке удаляет её, вставка нескольких строк из буфера раскладывает их по полям. Количество и единицы разбирает существующий `parseIngredientLine`.
- **Шаги** — отдельное многострочное поле на каждый шаг, «Add step» и удаление. (Решение 12.11.2026: одно общее текстовое поле на всё оказалось неудобным.)

Под раскрывашкой «Ещё»: источник, время, порции, описание.

- Коллекции, теги и фото в редакторе не показываются, но существующие значения при сохранении не теряются.
- Валидация: обязательно только название. Ингредиенты и шаги могут быть пустыми, но cook mode доступен только при ≥1 шаге.

### Cook mode

Без упрощений: это главная ценность продукта. Один UX-контракт для веба и [расширения](extension.md):

- крупный текущий шаг, длинный шаг делится на части по высоте экрана;
- внизу Previous/Continue/Next; ингредиенты в шторке с чекбоксами;
- таймеры по найденной длительности, запуск только по нажатию;
- ←/→ и Escape с клавиатуры;
- wake lock; таймеры по абсолютному `endsAt` ([правила PWA](../pwa-v1.md)).

Масштабирования порций и голоса в v1 нет.

### Настройки

Экспорт (W-06, JSON, бесплатно), смена пароля, тема, выход из других сессий, удаление аккаунта, ссылки на Privacy/Terms/поддержку. Профиль с именем — только если имя где-то используется; иначе убрать.

### Лендинг

Три блока и футер:

1. Hero: оффер и демо по ссылке (preview без аккаунта, «Сохранить в библиотеку» → регистрация с черновиком).
2. Расширение: что делает и «Добавить в Chrome».
3. Финальный CTA.

Блоки про коллекции и теги, «How it works» и пункт меню к нему убираются. В меню: «Chrome extension», «Sign in», «Create account».

### Pro

До P-01 нет paywall и кнопки «купить». После — gate только у импорта видео и соцсетей.

## Mobile / PWA

- Над первой карточкой только шапка. Без горизонтального скролла, зоны нажатия ≥44px, safe areas.
- PWA v1 остаётся **read-only офлайн** ([pwa-v1.md](../pwa-v1.md)): офлайн-баннер, кнопки записи disabled с объяснением.
- Android Web Share Target (W-12) ведёт в тот же поток импорта.

## MoSCoW

| Приоритет | Функция |
|---|---|
| Must | Лендинг с демо по ссылке; auth с возвратом к черновику; библиотека (поиск + сетка); карточка; добавление ссылкой и вручную; редактор из трёх полей; cook mode; PWA офлайн-чтение; экспорт; приватность и RLS |
| Should | Адресуемая карточка `/dashboard/recipes/:id`; Share Target Android; «уже сохранено» при повторной ссылке |
| Could | Вернуть одну из скрытых функций (коллекции **или** избранное), если её попросят пользователи |
| Won't v1 | Теги и коллекции в UI, избранное, сортировка, вставка текста, видео и соцсети, план питания, список покупок, публичные рецепты, масштабирование, голос, оплата |

## Решения

1. Мобильную колоду заменяет сетка (уже сделано в D-05).
2. Скрытые функции убираются только из UI. Данные, схема и экспорт их сохраняют.
3. Для записи обязательно только название (меняется `recipePayloadSchema`, БД не трогаем).
4. Адресуемая карточка — Should; до неё возврат из расширения идёт через `/dashboard`.

Документ служит входом для задач M-01…M-11, W-04, W-06, W-12 и E-02.
