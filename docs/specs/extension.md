# A-03 — Chrome-расширение v1.0

**Статус: утверждено владельцем 10.11.2026. Пересмотрено 11.11.2026: «минимальный v1», как в [web.md](web.md).** Вход: [A-01](../research/competitors.md), [A-02](../research/audience.md), [прототип v0.2.0](../../extension/README.md). Цель — получить чистый рецепт и начать готовить на чужом сайте без аккаунта, а сохранение довести до единой веб-библиотеки. Важное отличие от прототипа: все состояния и сообщения должны быть явно показаны, а не слиты в один текстовый `status`.

## Решения v1.0

- **Язык:** EN, как в вебе. Рецепт не переводим, единицы автора не меняем.
- **Запуск:** клик по иконке на конкретной вкладке. Автодетекта с бейджем в v1.0 нет. `activeTab` даёт временный доступ после действия пользователя и [не вызывает предупреждения о доступе ко всем сайтам](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab); постоянные host permissions для всех сайтов увеличили бы предупреждения при установке ([Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions)). Текущий постоянный доступ только к `keepandcook.com` остаётся для передачи черновика.
- **Сохранение:** через вкладку сайта с проверкой черновика и явным Save. Панель не хранит Supabase токены и не пишет рецепт напрямую. Переход должен ясно говорить, что рецепт ещё не сохранён.
- **Минимум в панели:** в шапке только логотип. Кнопка «Read this page» появляется лишь в состояниях ошибки и «нет рецепта», потому что чтение запускается само при открытии панели. Две кнопки действия: **Start cooking** (главная) и **Save**. Служебных подписей («Review and confirm…», «Check off what you have ready») нет; что рецепт ещё не сохранён, объясняет веб-редактор.
- **Приготовление:** полноэкранный по области страницы overlay; при запрете инъекции — отдельная вкладка. Большой текст, шаги/части длинного шага, чеклист ингредиентов, таймеры и wake lock. Voice в v1.0 нет.
- **Порции:** в v1.0 только показ исходных порций, без автоматического масштабирования. Сейчас `amount` хранится строкой; безопасный пересчёт смешанных единиц/дробей требует отдельного парсера и тестов. Нельзя выдавать математически неверные количества за корректные.
- **Экспорт:** `.txt` остаётся, но как мелкая ссылка «Download» внизу карточки, не кнопка. Print и PDF не делаем: браузерной печати достаточно. Источник включён в файл.
- **Без аккаунта:** читать, отмечать ингредиенты, готовить, запускать таймеры, скачивать. Аккаунт требуется только для облачной библиотеки.

## Пользовательские потоки

1. **Первое открытие:** установка → welcome-страница с одним примером сценария, объяснением доступа «только по клику» и CTA «Открыть сайт с рецептом»; без обязательной регистрации. По клику на иконку: загрузка → результат. Welcome не должен автоматически запрашивать новые разрешения.
2. **Чтение/готовка:** открыть рецепт на сайте → иконка → preview → отметить ингредиенты / Start cooking → шаги (Previous/Next/Continue step) → Finish → Save или Close. Прогресс чекбоксов живёт в текущей сессии вкладки; не обещать синхронизацию до сохранения.
3. **Сохранение, не вошёл:** Save → вкладка Keep & Cook с черновиком → вход/регистрация с возвратом к черновику → проверка данных → Save → открытая карточка в библиотеке. При email confirmation черновик восстанавливается, пока не истечёт срок передачи; если нет — понятная ошибка и повтор с панели.
4. **Сохранение, вошёл:** тот же переход минует экран входа; веб проверяет дубликат по нормализованной ссылке до записи. Если дубликат есть, показывает существующую карточку и действия «Open existing» / «Review as new» только если новый источник отличается; не создавать второй рецепт с тем же URL.
5. **Импорт не удался:** доступ к вкладке не получен → попросить нажать иконку/Retry; сайт не содержит рецепта → «No recipe found» с ссылкой на ручное добавление в вебе; серверный fallback недоступен или ограничен → отдельная ошибка с Retry и объяснением. Частично извлечённый рецепт показывать с предупреждением и возможностью правки в вебе, не маркировать как полный.
6. **Смена вкладки:** сбросить старую карточку сразу, привязать результат к `tabId` и URL, не показывать рецепт со старого сайта во время новой загрузки. Запретные страницы `chrome://`, Chrome Web Store и PDF объяснять как ограничение браузера.

## Состояния side panel

| Состояние | Условие | Что видно | Основное действие |
|---|---|---|---|
| Нет рецепта | Парсер завершил оба способа, результата нет | URL/домен, «No recipe found», короткая причина, ссылка «Add manually on web» | Retry / Read this page |
| Загрузка | Новая вкладка, запуск или Retry | Skeleton карточки + этап «Reading page» / «Trying website parser» | Можно закрыть; повторные запросы отменяются |
| Рецепт найден | Полный рецепт, без подтверждённого статуса аккаунта | Карточка, источник, cook/save/export | Start cooking |
| Ошибка доступа | `activeTab` не дан или вкладка ограничена | Никаких данных прежней вкладки; текст о разрешении | Нажать иконку на текущей странице / Retry |
| Ошибка извлечения | JSON-LD и fallback завершились ошибкой, сеть/429 | Различать unsupported, network, rate limit; не показывать внутренний stack | Retry; Add manually on web |
| Не вошёл | Веб после Save сообщил об auth gate | Карточка остаётся, статус «Sign in on Keep & Cook to save» | Continue in web |
| Вошёл | Веб подтвердил сессию для текущей передачи | Карточка + статус «Review and save in your library» | Continue in web |
| Уже в библиотеке | Веб вернул существующий рецепт для этого source URL | Плашка «Already saved» + ссылка на карточку | Open saved recipe |
| Сохранение завершено | Веб подтвердил запись | «Saved to your library» и ссылка | Open in library |

Последние четыре состояния приходят **только после явного перехода Save и ответа сайта**; панель не угадывает авторизацию по кукам и не опрашивает аккаунт в фоне. Если ответ из вкладки не пришёл, показывать нейтральный статус «Review in the opened tab», без ложного «Saved». Нужно привязать ответ к id передачи и origin сайта; не доверять сообщениям произвольных страниц. Для «уже в библиотеке» веб сравнивает URL в пределах текущего пользователя, не сообщает расширению другие данные библиотеки.

## Карточка и cook mode

Порядок карточки: 1) фото, если есть; 2) название; 3) домен/ссылка на источник; 4) время и порции, если распознаны; 5) предупреждение о неполных данных; 6) действия Start cooking и Save; 7) ингредиенты с чекбоксами; 8) шаги; 9) мелкая ссылка Download. Пустое поле не заполнять вымышленным значением. Ссылка на автора должна оставаться доступной; при прямом переходе на сайт источник виден всегда. Фото из прототипа не переносится при handoff, пока веб не сможет безопасно получить и сохранить его из `sourceUrl`; предупреждать о потере фото в редакторе, не обещать сохранение картинки.

Cook mode: вверху название, Close, Ingredients, видимые таймеры; в центре текущий шаг крупным шрифтом; внизу прогресс и Previous/Next. Длинный шаг разбивается по доступной высоте, «Continue step» не увеличивает номер шага. Ингредиенты — шторка с сохранёнными чекбоксами в этой сессии. Таймеры распознаются по длительностям в тексте шага, стартуют **только по нажатию**, показывают абсолютный дедлайн и после возвращения во вкладку пересчитывают остаток; правила звука и wake lock как в [PWA v1](../pwa-v1.md). В v1 таймеры не обещают уведомление, пока браузер/ОС не дают его гарантировать. Клавиатура: ←/→ — назад/вперёд; Escape — закрыть шторку, затем cook mode; Tab и Enter работают по стандарту, фокус удерживается в dialog. Voice — Won't для v1 (шум кухни, разрешения и локализация добавляют сложность).

## Утверждённые решения и вопросы реализации

1. **Print** — Won't; `.txt` — Must, но мелкой ссылкой.
2. **Порции без пересчёта** до появления проверенного парсера количеств.
3. Обратный статус **Saved/Already saved в панели** — Should; подтверждение в вебе обязательно. Точный механизм передачи статуса определяется при реализации E-02.

## Проверка перед утверждением / релизом

Прототип изучен по файлам и [задокументированному ручному чеклисту](../../extension/README.md). Попытка запустить установленный Chrome headless с `--load-extension` дала только страницу новой вкладки и не позволила проверить side panel; браузерное `Load unpacked` и сценарии **не были выполнены**, поэтому их нельзя считать пройденными. Перед релизом пройти вручную минимум: JSON-LD и fallback, переключение вкладки, ограниченная страница, signed-in/out с email confirmation, дубликат, ошибка сети, overlay/fallback, длинный шаг на 390×844, таймер после блокировки. Документ является входом для E-02…E-11 и D-12/D-13.
