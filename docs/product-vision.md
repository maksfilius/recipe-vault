# Концепт продукта

## Одной фразой

Keep & Cook — личная библиотека рецептов: рецепт можно забрать откуда угодно (сайт, видео, ручной ввод), хранить без рекламы и «истории жизни автора» и готовить по нему в удобном режиме пошаговой готовки.

## Проблема

- Рецепты на сайтах утоплены в рекламе, попапах и длинных вступлениях. Готовить по такой странице с телефона или ноутбука неудобно.
- Рецепты, которые хочется сохранить, разбросаны по закладкам, скриншотам, сохранёнкам в Instagram и YouTube.
- Существующие менеджеры рецептов (Paprika, Mela, ReciMe, Samsung Food) либо платные с первого дня, либо привязаны к одной платформе, либо перегружены функциями.

## Точки входа

Одна библиотека, несколько способов в неё попасть:

| Точка входа | Статус | Роль |
|---|---|---|
| Веб-приложение / PWA: ручной ввод | live | Ядро: хранение, поиск, коллекции, теги, избранное, cook mode |
| Веб: импорт по ссылке на сайт с рецептом | live | Основной способ пополнения библиотеки |
| Chrome-расширение | прототип | Вторая точка входа: открыл сайт → sidebar с чистым рецептом → cook mode → по желанию «Сохранить в библиотеку» |
| «Поделиться → Keep & Cook» на Android (Web Share Target PWA) | этап 1 | Сохранение с телефона из любого приложения без отдельного приложения в сторе. Заодно проверяет спрос на мобильный сценарий |
| Импорт по ссылке на YouTube | этап 2 | Главный кандидат в дифференциатор. Сначала бесплатно с лимитом, чтобы измерить спрос и себестоимость, на этапе 3 — Pro |
| Импорт из TikTok / Instagram | этап 3 | Pro, если допустимо по ToS (исследование A-07) |
| Приложения в App Store / Google Play | идея | Только после появления платящих пользователей |

### Расширение как воронка

Расширение полезно и без аккаунта: чистый рецепт и cook mode работают сразу. Регистрация нужна только для сохранения. Так расширение становится главным каналом привлечения: человек получает пользу на чужом сайте, а потом сохраняет рецепт и попадает в библиотеку.

```
Сайт с рецептом → иконка расширения → sidebar с рецептом → Cook mode
                                            └→ «Сохранить» → вход/регистрация → библиотека (веб/PWA)
```

## Аудитория (гипотезы, проверяет задача A-02)

1. **Домашний повар, который готовит с сайтов.** Несколько раз в неделю ищет рецепты в Google и устал от рекламы. Главная ценность для него — расширение и cook mode.
2. **Коллекционер рецептов.** Сохраняет всё подряд и теряет. Главная ценность — библиотека, поиск, коллекции и импорт из видео.
3. **Перебежчик с другого приложения.** Недоволен ценой или платформой Paprika, Mela и подобных. Главная ценность — веб плюс любая ОС и импорт из старого приложения.

## Принципы

- Рецепт полезен на всём пути, от находки до готовки.
- Связь с источником сохраняется: ссылка на оригинал есть всегда.
- Одна библиотека без отдельных «силосов» под каждую точку входа.
- Бесплатная часть должна быть по-настоящему полезной. Платим за то, что стоит денег (разбор видео, AI) или экономит много времени.
- Живой прод не ломаем.

## Монетизация (гипотезы, финализирует G-01 → P-01)

- **Free:** библиотека, ручной ввод, импорт с сайтов, расширение (просмотр, cook mode, сохранение), PWA.
- **Pro (~$3–4 в месяц или ~$30 в год):** импорт из видео и соцсетей, а также 1–2 функции, которые выберет спецификация (кандидаты: список покупок, план питания, масштабирование порций, экспорт и импорт из других приложений, расширенный офлайн).
- Лимит на число рецептов во Free считается крайней мерой: он бьёт по главной ценности хранилища.
- Для налогов на соло-проекте предпочтителен провайдер в роли Merchant of Record (Paddle или Lemon Squeezy), решение принимается в P-02.

## Метрики Северной звезды

- **Активация:** пользователь сохранил ≥3 рецептов за первые 7 дней.
- **Удержание:** еженедельные активные «повара», то есть открывшие cook mode или рецепт из библиотеки.
- **Расширение:** доля установок, после которых был хотя бы один сохранённый рецепт.
- **Монетизация:** конверсия Free → Pro, число платящих.

## Открытые решения

- Язык продукта и рынок: интерфейс сейчас на английском. Нужна ли русская (или другая) локализация на старте? Решается в A-02 и A-03.
- Нужен ли расширению автодетект рецепта (бейдж на иконке)? Для него нужны широкие host permissions, что отпугивает при установке. Решается в A-03.
- Сохранение из расширения: прямое через API (нужна авторизация в расширении) или через вкладку сайта, как сейчас. Решается в A-03 и E-02.
