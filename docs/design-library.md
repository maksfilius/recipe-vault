# D-05 — библиотека рецептов

Основной вид на телефоне и десктопе — адаптивная сетка карточек. На узком телефоне одна колонка, с `sm` две, с `lg` три, с `xl` четыре. Мобильная колода удалена: она скрывала обзор большой библиотеки и результаты поиска.

Поиск охватывает название, описание, ингредиенты, теги и названия коллекций. Коллекции объединяются по OR, выбранные теги — по AND; поиск сочетается с обоими фильтрами. URL-параметры `q`, `collections`, `tags` сохраняются. Изменения пишутся в историю браузера, поэтому Back восстанавливает запрос и выбранные фильтры. Сортировка: дата добавления, дата обновления, название A–Z; при равенстве порядок исходного списка сохраняется.

Счётчик показывает число рецептов или «N of M recipes» при фильтрах. Для пустой библиотеки, пустого результата и ошибки загрузки есть отдельные состояния. В избранном применены та же сетка карточек, состояние загрузки, пустое состояние и офлайн-снимок.

## Проверка

Для проверки интерфейса использована временная копия приложения с локальными наборами из 0, 1, 10 и 200 рецептов. В исходном приложении тестовые рецепты не создавались. На ширине 390 px у всех четырёх наборов `document.documentElement.scrollWidth` был равен 390 px, число карточек и счётчик совпали с набором. Проверены светлая и тёмная темы на 1440 px. Снимки: [0](screenshots/kc-d05-mobile-0.png), [1](screenshots/kc-d05-mobile-1.png), [10](screenshots/kc-d05-mobile-10.png), [200](screenshots/kc-d05-mobile-200.png), [desktop light](screenshots/kc-d05-desktop-10-light.png), [desktop dark](screenshots/kc-d05-desktop-10-dark.png).

В браузере проверены URL-поиск, фильтры коллекции и тега, ввод запроса, два последовательных Back, очистка фильтров и сортировка. Чистый запуск `npm run test` завершился с 63/63 тестами; `npm run build` собрал маршруты `/dashboard` и `/dashboard/favorites`.

Следующее развитие пустой библиотеки с тремя равноправными действиями относится к W-04 согласно `docs/specs/web.md`.
