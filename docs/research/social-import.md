# A-07 — импорт рецептов из видео и соцсетей

Исследовано 10.11.2026 для EN/US старта. Главный вывод: **первым делать YouTube через официальную выдачу описания и ссылку на рецепт автора**. Произвольные субтитры, аудио и видео не считать доступными только потому, что ролик публичный. Пользователь всегда проверяет черновик перед Save. TikTok и Instagram пока не обещать как автоматический импорт по любой ссылке.

## Источники данных и допустимый сценарий

| Платформа | Что доступно официально | Что даёт для рецепта | Ограничение / решение |
|---|---|---|---|
| YouTube / Shorts | [`videos.list(part=snippet,contentDetails)`](https://developers.google.com/youtube/data/reference/rest/v3/videos/list) по ID: название, описание, thumbnail, признак captions; 1 quota unit | Описание может содержать полный рецепт или ссылку автора. Shorts обрабатываются как тот же ID. | API key только на сервере; не предполагать, что описание содержит шаги. Если есть ссылка на сайт автора, предложить импорт сайта с сохранением исходной ссылки на видео. |
| YouTube captions | [`captions.list`](https://developers.google.com/youtube/data/reference/rest/v3/captions/list), [`captions.download`](https://developers.google.com/youtube/data/reference/rest/v3/captions/download) | Текст речи потенциально содержит метод | Официальная загрузка требует авторизации/прав; для произвольного чужого ролика надёжного доступа нет. `timedtext`, yt-dlp и аналогичное получение не включать в продуктовый путь: [YouTube запрещает scraping и загрузку аудиовизуального контента без разрешения](https://developers.google.com/youtube/terms/developer-policies). |
| TikTok | [`oEmbed`](https://developers.tiktok.com/docs/en/embed-videos) — embed/основные метаданные; [Display API](https://developers.tiktok.com/docs/en/display-api-get-started) — ролики **авторизованного создателя** с `video.list` | Публичный embed не даёт надёжный набор ингредиентов/шагов; собственные ролики автора — отдельный OAuth сценарий | [Условия TikTok в США запрещают автоматическое извлечение без письменного разрешения](https://t.tiktok.com/legal/page/us/terms-of-service/en). Не строить произвольный импорт через скрейпинг или скачивание видео. |
| Instagram / Reels | [Официальный Instagram API Meta](https://www.postman.com/meta/instagram/collection/6yqw8pt/instagram-api) рассчитан на Business/Creator и управление разрешёнными объектами; oEmbed предназначен для показа публичной публикации | Метаданных embed недостаточно для рецепта произвольного автора | Не считать Graph API доступом к любому публичному Reels. Для реализации проверить актуальные Meta Platform Terms и разрешения App Review; пока поддерживать вставку текста или ссылку на сайт автора вручную. |

**Аудио → транскрипция:** технически возможно только при правомерно полученном аудио (например, собственный файл пользователя или отдельное разрешение автора/платформы). Для публичных YouTube/TikTok/Instagram URL этот шаг не входит в MVP. Ни API key, ни модель транскрипции сами по себе не дают права скачивать медиаданные. Хранить оригинальную ссылку, автора/атрибуцию где доступны; не публиковать импортированные рецепты как контент Keep & Cook.

## Проверка 10 реальных видео

Это **ручная оценка доступности исходного текста**, а не тест LLM или официального YouTube API: описания видны в индексированной выдаче YouTube; ключ API и вызовы модели в этой задаче не использовались. Выборка намеренно разнообразная, поисковая, не статистически репрезентативная. `Полный` = в описании видны количества ингредиентов и последовательные действия; `частичный` = одна из этих частей; `ссылка` = детали на внешнем сайте/в ролике. Описание по API может отличаться от индексированной копии.

**Итог входного качества: 5/10 полных, 1/10 частичный, 4/10 ссылка на внешний рецепт.** Это потолок для гарантированного полного черновика *из одного описания* в этой выборке, а не измеренная точность LLM. На пяти «полных» качество извлечения полей и пригодность черновика ещё необходимо измерить вызовами модели и ручной сверкой; критерий X-01 `≥7/10` из текущего description-only пути недостижим без использования ссылок автора. Из четырёх ссылочных случаев как минимум Maangchi и Preppy Kitchen ведут к отдельным рецептам автора; перед X-01 проверить все конечные URL через официальный `videos.list` (индекс заменяет адреса на `URL`) и существующий парсер сайтов. Не считать ссылки на магазины или соцсети рецептом.

## Структурирование и стоимость

Сначала детерминированно выделять блоки `Ingredients/Instructions/Directions`, проверять количества и ссылку на сайт автора; LLM вызывать только на уже полученном текстовом рецепте или неоднозначном блоке. Модель возвращает строгий JSON с `title`, `ingredients[]`, `steps[]`, `servings?`, `warnings[]` и источником каждого поля; не достраивает пропущенные количества/шаги. Пользователь видит предупреждение о неполном импорте и редактирует до Save.

Ориентир по [ценам Claude API на 10.11.2026](https://platform.claude.com/docs/en/models/haiku-5-5/overview): Haiku 5.5 до 100k входных токенов — **$0.10 / 1M input** и **$0.50 / 1M output**. При 2 000 input + 500 output — ~$0.00045 за LLM-вызов; при 5 000 + 1 000 — ~$0.001. Для осторожного бюджета по [legacy Haiku 4.5](https://platform.claude.com/docs/en/models/haiku-4-5/overview), $1/$5 за 1M, те же объёмы стоят $0.0045 и $0.010. Это арифметическая оценка **одного** вызова без retries, tool-use, налогов, транскрипции, хостинга и ручной проверки. Фактический счёт определять по логам токенов на 10 роликах и ставить лимит попыток на пользователя. API YouTube использует quota units, а не прямую оплату за каждый `videos.list`.

## Рекомендация для X-01

1. Поддержать `youtube.com/watch`, `youtu.be` и Shorts через один video ID. Серверный `videos.list` получает `snippet.description`, title, thumbnail. Записать версию политики и дату доступа к API, ключ держать на сервере.
2. Если описание содержит оба блока — извлечь и показать редактируемый черновик; при необходимости вызвать Haiku с JSON-схемой. Если есть ссылка на **сайт автора с рецептом**, предложить импорт этой страницы существующим парсером, сохранив видео как дополнительный источник/атрибуцию. Если текст только частичный — показать, чего не хватает, и разрешить ручное дополнение.
3. До разработки проверить на этих 10 видео фактические description через API, ссылки автора и результат LLM; считать успехом только черновик с корректными ингредиентами и шагами после ручной сверки. Не обещать ≥7/10 до этого замера.
4. TikTok/Instagram отложить до подтверждённого разрешённого источника текста. В качестве промежуточного пользовательского сценария оставить вставку текста/ссылки на сайт автора без автоматической загрузки контента платформы.

## Открытые вопросы

- Есть ли у проекта YouTube Data API key и достаточная квота для теста; нужен доступ к 10 фактическим описаниям и конечным ссылкам.
- Можно ли сохранять ссылку на видео отдельно от `source_url` сайта автора без изменения схемы БД; решить до X-01.
- Требуется юридическая проверка политики хранения метаданных YouTube и условий Meta/TikTok для конкретных рынков.
