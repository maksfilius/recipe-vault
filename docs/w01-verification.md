# W-01: проверка рефакторинга библиотеки

Ручной прогон 10.11.2026 проведён в Chrome с локальным Supabase и отдельным тестовым пользователем. Проверены:

- регистрация и загрузка пустой библиотеки;
- создание коллекции и рецепта, редактирование описания, удаление коллекции без удаления рецепта, удаление рецепта с подтверждением;
- поиск с `?q=`, фильтры коллекции и тега с `?collections=` и `?tags=`, очистка фильтров с сохранением поискового запроса;
- добавление в избранное и отображение на странице Favorites;
- офлайн-снимок из IndexedDB: рецепт доступен для чтения, изменяющие действия заблокированы;
- восстановление черновика из `keep-and-cook:pending-recipe-import`: редактор открывается с заполненным названием, запись в sessionStorage удаляется.

`dashboard/page.tsx` содержит 7 строк. Загрузка и офлайн-снимок находятся в `useDashboardData`, фильтры и URL — в `useDashboardFilters`, восстановление черновика — в `useDashboardImport`, операции — в `useDashboardActions`, диалоги — в `DashboardDialogs`.

Обычный `npx supabase start` в текущем дереве не проходит: две миграции начинаются с `20260805`, и CLI выдаёт `duplicate key value violates unique constraint "schema_migrations_pkey"`. Для этого прогона использована копия `supabase/` во временной папке с отдельным номером второй миграции. Исходные файлы миграций не менялись. Локальные сервисы после проверки остановлены. Конфликт имён миграций нужно устранить отдельной задачей до W-11.
